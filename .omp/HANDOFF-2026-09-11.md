## What was tried — four lessons paid for in real bugs

A correctness review of all 117 PR commits found 18 defects. All are now fixed.

1. **A Go nil slice marshals to JSON `null`, and the TypeScript types declare non-nullable arrays.**
   This shipped FOUR separate crashes on this branch — `report.errors`, `PayloadSet.Dropped`,
   `BucketExample.Payloads`, `Finding.Occurrences` — each of which blanked a whole tab via the
   ErrorBoundary. Go cannot see it: nil and empty slices have identical `len` and `range`, so every
   existing test passed against either. **If you add a slice wire field, initialise it non-nil and
   assert the MARSHALLED JSON, not the struct.**
2. **A setting that is parsed and never consulted is the signature defect here.** Three found:
   `insertion_point_types` restricted only the audit-queue *display* while all 15 probe sites used a
   hardcoded literal (so disabling cookie insertion did not stop payloads going into cookies);
   `GateCheck` had one caller, so "Pause all tasks" paused only the sequencer;
   `ProtocolPreferenceForceH2` produced a plan `reflect.DeepEqual` to Auto. **Grep your new
   setting's identifier and count the call sites before claiming it works.**
3. **The e2e harness serves `dist/app.js`, not your sources.** Browser-verifying without
   `bun run build` first gives a false pass. Caught twice today.
4. **Grep silence is not evidence.** One positive control was silent because reverting a block left
   an import unused — the package did not build, so the grep for a failure line found nothing.

## Usage monitoring (why this handoff happened) — AND A WARNING

`~/.claude/bin/quota-check` reports 5-hour usage. It prefers the REAL number,
`rate_limits.five_hour.used_percentage`, which Claude Code pipes to the statusline command's stdin
and the OMC HUD tees to `~/.claude/hud/cache/stdin.<session>.json`.

**Do not trust its fallback.** In a headless session the statusline never renders, so that cache
goes stale and the script falls back to a ccusage estimate: the active 5-hour block measured against
the largest block this account has previously completed. At handoff that fallback read **70%** while
the real figure was **98%** — the user had to correct it. The peak-block baseline is not the ceiling
and underestimates badly.

If you need a reliable reading, get the real field: either run in a context where the statusline
renders, or ask the user to check `/usage`. Treat the estimate as a lower bound only.
