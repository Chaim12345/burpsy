<objective>
Build `crates/core/src/segment.rs`: the sealed, self-describing, mmap-backed segment log that STORE-01
needs. Nothing in this plan touches `TrafficStore` — the module is standalone and independently
testable, so the risky I/O lands and is proven before plan 01-03 ports the store onto it.

Purpose: captured traffic must become bounded by disk rather than RAM. The bound comes from exactly
one segment being resident (the active, unsealed one); every sealed segment is a read-only mmap
wrapped once in `Bytes::from_owner`, so a multi-GB capture costs one target-sized RAM buffer plus a
page cache the OS is free to evict.

Output: `crates/core/src/segment.rs` with the record/segment header format, `SegmentLog`
(append/resolve/seal), the rotation policy including the oversized-message divergence from Kafka, and
its own test module. Plus `memmap2` and `crc32fast` added to `crates/core`.
</objective>

<interface_contract>
Plan 01-03 ports `TrafficStore` onto exactly this surface and plan 01-05 builds `verify_dir` on
`scan_segment_file`. These signatures are the contract; do not rename or reshape them without
updating both dependents.

```
pub const SEGMENT_MAGIC: [u8; 8]                    // *b"BURPSYSG"
pub const SEGMENT_FORMAT_VERSION: u8                // 1
pub const SEGMENT_FILE_HEADER_LEN: usize            // 16 = magic(8) + version(1) + reserved(7)
pub const RECORD_HEADER_LEN: usize                  // 17 = len(4) + msg_id(8) + direction(1) + crc32(4)
pub const DEFAULT_SEGMENT_TARGET_BYTES: usize       // 64 * 1024 * 1024

pub struct Location { pub segment: u32, pub offset: usize, pub len: usize }
pub struct RecordHeader { pub len: u32, pub msg_id: MsgId, pub direction: Direction, pub crc32: u32 }
pub enum CorruptRecord { ShortHeader { at: usize, need: usize, have: usize },
                         UnknownDirection { at: usize, byte: u8 },
                         LengthOverrunsSegment { at: usize, declared: usize, segment_len: usize },
                         ChecksumMismatch { at: usize, id: MsgId, stored: u32, recomputed: u32 } }
pub struct SegmentScan { pub index: u32, pub records: Vec<(RecordHeader, Location)>,
                         pub corruption: Option<CorruptRecord> }

impl RecordHeader { pub fn encode(&self) -> [u8; RECORD_HEADER_LEN];
                    pub fn decode(at: usize, bytes: &[u8]) -> Result<Self, CorruptRecord> }

pub struct SegmentLog;
impl SegmentLog {
    pub fn open(dir: &Path, target_bytes: usize) -> anyhow::Result<Self>;
    pub fn append(&mut self, id: MsgId, direction: Direction, payload: &Bytes) -> anyhow::Result<Location>;
    pub fn resolve(&self, loc: Location) -> Option<Bytes>;
    pub fn header_at(&self, loc: Location) -> Result<RecordHeader, CorruptRecord>;
    pub fn seal_active(&mut self) -> anyhow::Result<()>;
    pub fn flush_active(&mut self) -> anyhow::Result<()>;
    pub fn dir(&self) -> &Path;
    pub fn segment_count(&self) -> usize;
    pub fn sealed_count(&self) -> usize;
    pub fn resident_bytes(&self) -> usize;
}

pub fn segment_file_name(index: u32) -> String;                  // "segment-000000.log"
pub fn scan_segment_file(path: &Path) -> anyhow::Result<SegmentScan>;
```
</interface_contract>

  <action>
    Implement `seal_active(&mut self) -> anyhow::Result<()>` in `crates/core/src/segment.rs` as an
    explicitly ordered sequence, with a comment stating that the order *is* the safety argument and
    that reordering any two steps reintroduces either a remapped-live-mapping hazard or a
    trusted-corrupt-segment hazard:
    1. `flush()` the `BufWriter`, then `sync_all()` the inner `File` (fsync).
    2. Drop the writer, so nothing holds a write handle.
    3. `std::fs::rename` the `.tmp` path to `segment_file_name(index)` in the same directory (atomic on
       one filesystem).
    4. `scan_segment_file` the renamed path and return `Err` if `corruption` is `Some`, with the error
       message naming the byte offset and the failing record's id. A segment that fails its own scan is

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| captured traffic → segment file | Attacker-influenced response bytes are written verbatim to disk. The payload is never parsed by the segment layer, but its declared length and CRC are read back and trusted on resolve. |
| segment file → mapped `Bytes` | Once mapped, a record header's declared length becomes an index into a live mapping. A lying length is an out-of-bounds read unless bounds-checked. |
| local filesystem → this process | Another local process (or a bug, or disk failure) can truncate or rewrite a sealed segment file that this process has mapped. |
| crates.io → build | `memmap2` and `crc32fast` enter the dependency tree. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-02 | Tampering | `scan_segment_file`, `seal_active` | high | mitigate | Every record carries a `crc32fast` checksum over its payload, written at append. `seal_active` scans the whole renamed file and refuses to map a segment with any fault, naming the byte offset and record id. ASVS V6 note: CRC32 is corruption detection, not a cryptographic integrity control, and the module header says so. |
| T-1-03 | Tampering / DoS | `SegmentLog::resolve`, `RecordHeader::decode` | high | mitigate | `resolve` bounds-checks `offset + len` against the segment's actual length with `checked_add` before slicing and returns `None` on overrun — mirroring `StoredMessage::slice`'s existing guard. `decode` refuses a short buffer and an unknown direction byte by naming the offset and value; a malformed header is a report-corruption case, never a silent skip. |
| T-1-04 | Denial of Service | sealed segment mmap | medium | mitigate | Exclusive ownership: only this process creates, renames, or removes files under the capture directory, and a sealed file is never written again, so a live mapping is never remapped. The residual (a hostile local process truncating a mapped file, causing a fault on access) is stated honestly in the `seal_active` comment and detected by the CRC scan rather than prevented. |
