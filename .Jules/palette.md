## 2026-08-03 - [Repeater Keyboard Shortcuts & Focus Indicator Usability]
**Learning:** Keyboard-only operators rely heavily on keyboard shortcuts and intuitive focus navigation. In proxy environments like Repeater, having to manually tab to or click a "Send" button is a heavy cognitive and physical strain. Standardizing `Ctrl+Enter` and `Cmd+Enter` shortcuts on the edit pane and the URL target input, and mapping `Enter` on input to a trigger, makes the flow completely seamless and mirrors core desktop tooling behaviors (like Burp Suite). Adding `tabindex="0"` on read-only block components (like `<pre>` containing response data) is a vital a11y requirement to allow keyboard-only users to scroll through large content. Focus-visible state boundaries are required to make interactive elements accessible to keyboard-based navigators.
**Action:** Always include keyboard shortcut options on primary actions (such as form submits and request executions) and verify scrollability of read-only response panels for keyboard users.
