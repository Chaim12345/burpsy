# scanner

## Purpose

The active audit engine, passive BCheck scanning, and Burp's shipped issue catalog transcribed. This
is the Go port of `crates/scanner`, but it has grown well past the Rust reference: where the Rust
crate documents "two native checks, off by default", the Go package carries a full typed check
registry — active injection, DOM (headless browser), stored/second-order, collaborator/out-of-band,
CORS/CSP/cache, passive posture and analysis families — assembled in `check_registry.go`.

Scanning is off the proxy's hot path and active scanning is never automatic: it is operator-triggered
because it sends traffic to the target. The bounding model is Burp's inverted — work is refused at an
**admission gate before a request is built, and counted**, rather than expanded and discarded
(`LIMIT_EXCEEDED`). Every refusal carries a named `Disposition`; a count without a reason is not
acceptable output here, so a caller can always tell "looked and found nothing" from "stopped
looking".

## For AI Agents

- **`catalog_data.go` is generated — never hand-edit it.** It is ~3.7k lines of literals produced
  from the Burp Suite 2026.7.1 jar extraction. Edit `tools/gen_catalog.py` and regenerate with
  `python3 internal/scanner/tools/gen_catalog.py internal/scanner/catalog_data.go`. Hand edits are
  clobbered on the next regenerate and produce an unreviewable diff.

- **`TypeIndex` vs `DeclaredTypeIndex` disagree in 2 of 183 cases, on purpose.** `TypeIndex` is
  the filename ID (unique); `DeclaredTypeIndex` is the `typeIndex` inside the JSON body. Both are
  kept verbatim rather than reconciled — silently picking one would lose the forensic fact that the
  shipped data disagrees with itself. There is no CVSS anywhere in the catalog, so no CVSS field
  exists. Remediation is transcribed, never invented; `Remediation` is empty exactly when the
  source has none (14 of 183), so an absent one can never read as "nothing to do".

- **Every check family is off by default and has its own `ScanConfig` switch.** The many
  `CheckExtendedActive`, `CheckPassiveAnalysis`, `CheckActiveInjection`, `CheckDOM`, etc. flags
  are all off by default because most catalog rows have no individual Java toggle either — admitting
  them unconditionally would silently change what "the checks I enabled" means for every caller.
  `CheckOutOfBand` only *widens* `CheckExtendedActive`; enabling it alone admits nothing.

- **Native checks are built lazily and reused across audits.** `ActiveScanner.jsLib`/`jwtWeak` are
  filled once (`nativeOnce`) rather than per exchange — re-parsing the ~514 KB retire.js corpus for
  every audited exchange would dominate the scan. `With…` setters override before first use.

- **Every native/declined descriptor must name a real catalog issue.** `nativeDescriptor` and
  `declinedDescriptor` call `ByName` and **panic** if the name is absent from the catalog. New
  checks use the catalog's exact issue name so `enrich` attaches Burp's own remediation.

- **Scope enforcement does not live here.** The audit path takes an authorising sender; scope is
  checked against the bytes actually going on the wire in `internal/sender`. Do not re-add a scope
  check inside this package — that is the anti-pattern the sender chokepoint exists to remove.

- **`AuditSession` shares one budget/ledger/breakers across a batch; `AuditWithin`/`Audit` are
  one-shot with a fresh ledger.** A `given host` check auditing 500 exchanges on one host dispatches
  once and attributes the other 499 as already-covered. Do not collapse scope across single audits to
  "save work" — an operator who clicks audit again means it.

- **`OptUint32` exists because absent ≠ zero.** Zero *disables* a breaker (Burp's "never stop"
  preset); absent means "inherit the default". A plain uint32 would make the shipped presets
  unrepresentable. `AuditLedger` carries its own mutex because `AuditSession` audits concurrently —
  Rust got exclusive access for free from `&mut self`.

- **A nil finding slice is a clean result, not an unsupported one.** A `CheckRunner` signals refusal
  through its returned error (classified by the engine), never by returning nothing.

- **Load-time classification is not runtime coverage.** `LoadReport` records what parsed and bucketed
  at startup; `CoverageReport` records what ran on live traffic. Keep them distinct — the whole
  project value is honest counting, so a partial state must never read as complete.

## Testing Requirements

```bash
go test ./internal/scanner/...
```

The runtime-coverage tests (`runtime_coverage_test.go`) stand up a live vulnerable target and a real
sender; DOM tests are gated on Chrome being on `PATH` (`chromeOnPath`). Tests are named as full
sentences stating a claim.

## Dependencies

### Internal (`internal/`)

- `core` — the traffic store, `Exchange`, `Scope`, exchange IDs, findings
- `bcheck` — the BCheck parser/evaluator, `InsertionPoint`, `IpKind`, `ToolRunner`
- `sender` — the one authorised path to a socket; probes and audit requests go through it
- `domexec` — the shared headless browser and taint `Observation`s for DOM checks
- `session` — the `Coordinator` the access-control and CSRF rows need

### External

`go.uber.org/zap` (logging), `projectdiscovery/wappalyzergo` (technology fingerprinting in
`infra_fingerprint.go`). Unlike the Rust crate — which deliberately has no async runtime — the Go
package reaches transport and a browser through the internal packages above rather than pulling those
capabilities in directly.
