## Registering a page

Five places must be updated, and tests fail if any is missed:

1. **Router:** `server.go` `setupRoutes` has one `s.route("/ui2/...", s.handleUI2X)` per pattern, all literals, before the `/` catch-all (lines ~1523–1585).
   - `routes_register.go` `route()` panics at startup if a pattern has no manifest entry.
   - It adds `Cache-Control: no-store` to every `/ui2/` route, because pages can show cookie-jar values.
   - It answers verbs not in the manifest with 405.
2. **Manifest:** `route_manifest.go` `manifest`, kept sorted. Every ui2 page and action is `risk: riskAsset`, with an exact `methods` list and a `subPath` for wildcard patterns (for example `"1/stop"` or `"confirm"`).
   - The one exception is `/ui2/sitemap/repeater`, which is `riskRead`.
   - Comments explain why: if the review route itself were credential/scope-classed, the confirmation gate would answer the operator's own confirm POST with 428.
3. **MCP:** `internal/mcp/groups.go` `notExposed` has a `"VERB /ui2/..."` entry with a reason for every route-verb (around lines 521–584), pointing at the `/api/*` route agents should use instead.
   - `internal/mcp/tools.go` `annotationsForRoute` sets readOnly/idempotent to false whenever a route takes a mutating verb, because ui2 POSTs are classed `riskAsset` (commit 652523d2).
4. **Input schemas:** `route_schemas.go` declares every mutating ui2 route-verb as a form-encoded raw body, or `noBody`.
5. **Test exemption lists:** `ui_route_reachability_test.go` `uiRouteExempt` and `json_nil_slice_test.go` `nonJSONAsset` (markers `&lt;!doctype html` / `text/javascript`).
   - Derived TypeScript and fixture files are regenerated: `ui/src/lib/gated-routes.ts`, `route-risk.ts`, `gated-routes.contract.json` (via `BURPSY_UPDATE_GATE_CONTRACT=1`) and `api-schema.d.ts`.

## Templates

- **Layout:** `layout.html` is the only shell.
  - It renders `ui2Page{Title, View, Body}` and includes `{{template "nav" .}}` from `nav.html`.
  - CSS is inline, using CSS variables and `data-theme`.
  - It provides `#notice`, `#busybadge`, `#sel-count` and the theme toggle.
  - `main` holds `#list` and `#detail`. It gets class `split` for history, issues, intruder and advisories.
  - The History filter form lives in the header, outside `#rows`.
- **Naming:**
  - `&lt;page&gt;.html` for the page fragment.
  - `&lt;page&gt;_confirm.html` / `*_confirm.html` for review sheets.
  - `*_rows_append.html` for infinite-scroll appends.
  - `settings_write_&lt;area&gt;.html` for lazily loaded settings sections.
  - `error.html` takes `ui2Error{Message}`.
- **Shared Go helpers:**
  - `ui2RenderPage` renders the full shell.
  - `ui2Fragment` returns just the fragment when `HX-Request: true`, otherwise the shell.
  - `ui2Exec(name, model)` renders a template to a string.
  - Models are mostly `map[string]any` decoded from API JSON, plus typed structs for history and issues.
- **Template functions:** `lower`, `urlquery` (for a NUL-carrying site-map key in an `hx-post` URL), `until`, and `ms` (epoch-millis to time).

## How data is fetched

There are two styles.

- **In-process calls to the JSON API (the main style).** The stated aim is that "ui2 and the JSON API cannot drift." This works in two ways:
  - Calling the handler methods directly with a recorder: `newReq(method, "/api/...")` builds a request to `http://console.invalid/...` and `newRecorder()` captures the reply. Examples: `s.sitemapGet`, `s.getScope`, `s.handleIntercept`, `s.toolLogGet`, `s.handleWSConnections`, `s.handleExtensions`.
  - Going through the inner `s.mux`, which skips the gates: `s.mux.ServeHTTP`, `ui2APIResult(method, path, payload)` and `ui2CanonicalGet`.
- **Direct calls to Go services.**
  - History and Issues: `s.store.Exchanges()`, `compileQuery`, `exchangeView`, `s.findings.All()`, `s.issueView`, `s.exchangeIndexFor`.
  - Dashboard: `s.store.Count()`, `s.tasks.*`, `s.toolLog`, `s.events`.
  - Repeater draft and `ui2LatestExchange`: `s.store`.
  - Held intercept messages: `s.intercept.Held()`.
  - Organizer: `s.organizer.*`.
  - Session: `s.sessionCoordinator.RuleSnapshot` / `UpdateRuleIfUnchanged`.
  - Definitions detail: `s.advisories.ByIndex`.

## How writes work (three mechanisms)

**A. Review against the API's own confirmation gate** (`ui2_attack_pages.go`):
- `ui2MintConfirm(apiPattern, method, url, body)` POSTs `{method, url, body|body_base64}` to `s.confirmMux` at `&lt;pattern&gt;/confirm`. It returns the token plus a preview cut to 200 characters; some sheets show the full body as `full_body`.
- `ui2DispatchConfirmed(method, path, payload, token)` sends the call through `s.guarded` (same-origin check plus confirmation gate). It sets `X-Burpsy-Confirm`, `Host: 127.0.0.1` and `Origin: http://127.0.0.1`, and maps 428 to "confirmation required".
- The flow is always: POST `/ui2/&lt;page&gt;/confirm` (or `launch`) mints a token and renders a review sheet with hidden fields. "Confirm and run" POSTs `/run` with the token. The run step rebuilds the body with the same function (for example `ui2ScopeAPIPayload`, `ui2CrawlPayload`, `ui2IntruderRunPayload`, `ui2LoggerFilterForm`), so any edited field no longer matches the token's digest and the gate refuses.
- Used by: Scope rules and libraries, Site map add-to-scope, Scanner audit, crawl and config, Intruder run, Sequencer capture start, Logger capture and filter.

**B. Review entry held on the server, dispatched verbatim:**
- The exact call is stored in a `sync.Map` on `Server`: `ui2TriageReviews`, `ui2SessionRuleReviews`, `ui2SettingsWriteReviews`, `ui2CollectionReviews`, `ui2WorkflowReviews`, `ui2AnnotateReviews`, `ui2ItemReviews`. Each is keyed by `randomHex(16)`, capped at 8 entries, swept when a new one is issued, and expires after `ConfirmTTL` (60 s).
- The run form carries only `review_id` and `token`. The run step does `LoadAndDelete` (single use) and compares tokens with `subtle.ConstantTimeCompare`.
- How the token is made and the call dispatched depends on the area:
  - **Triage, session rules, pool writes:** the token comes from the gate, and the call goes through `s.guarded`.
  - **Session rule toggle/edit and action editing:** install happens at the domain level with `session.UpdateRuleIfUnchanged` under a `RuleDigest` precondition, because the wire DTO drops `Validity` and `ExtensionSession`.
  - **TLS passthrough, upstream proxy, backup:** these are ungated `riskLocal` routes. The token is a local one-use handle and the call goes through `s.mux`. Backup and pool writes re-read state and refuse if it changed since review.
  - **Organizer:** `s.confirms.issue("ui2-collection"|"ui2-workflow"|"ui2-annotate"|"ui2-item", newCallBinding(POST, "/ui2/organizer/.../install", "", body))` and `s.confirms.spend`. The change is then applied through `s.organizer.*IfUnchanged`, with SHA-256 `form_base` digests to detect edits made elsewhere.
- Strict field rules: `ui2CollectionFields`, `ui2WorkflowFields`, `ui2AnnotateFields`, `ui2ItemOpFields` and `ui2SitemapFields` accept each permitted field exactly once, nothing else, and no query fields.

**C. Collaborator mint (local only):** `handleUI2CollaboratorMint` holds `ui2PendingMint{body, expires}` in `s.ui2Mints` for 60 s. The confirm step sends only `mint_id`. This route is `riskEgress`, which the gate doesn't cover.

**Direct one-click writes with no review:**
- Intercept enable/disable, forward-all, drop-all, per-item forward/drop with edits, and the active switch on rule lists (all `riskLocal`).
- Repeater send (`riskEgress`, ungated).
- Intruder pause/resume/stop.
- Sequencer pause/resume/stop.
- Alt+T in `app.js` calls `fetch` POST `/ui2/intercept/enable|disable`.

**Origin checks:** browser requests reach handlers through `s.guarded = s.sameOriginOnly(s.confirmationGate(s.mux, s.confirmMux))`. `api_sameorigin.go` describes three checks:
- `Host` must be loopback or allowlisted, on every method.
- `Sec-Fetch-Site` and `Origin` must be same-origin, on mutating methods only.

Because ui2 routes are `riskAsset`, the confirmation gate doesn't apply to them; it applies to the `/api` calls they make.

## htmx patterns

- **History:**
  - Header filter form: `hx-get="/ui2/history" hx-target="#rows" hx-swap="outerHTML" hx-trigger="submit, keyup changed delay:400ms" hx-push-url="true"`. The URL keeps the filter state, so views can be bookmarked.
  - Rows: `hx-get="/ui2/history/{id}" hx-target="#detail"`.
  - Infinite scroll uses a sentinel row: `hx-trigger="intersect once" hx-swap="beforeend"` into `#rows-body`.
  - The sentinel's `hx-vals` is JSON built on the server (`ui2HistoryHxVals` / `ui2LoggerHxVals`), so filters containing quotes survive. When `offset` is present the handler returns only the rows (`history_rows_append.html`, `logger_rows_append.html`).
- **Pretty/Raw toggle:** `?view_req=raw|pretty&amp;view_resp=...` on the detail pane.
- **Lazy settings sections:** `hx-trigger="load"` on `/ui2/settings/write/{area}`.
- **Review buttons:** rendered `disabled data-arm-on-load` and enabled by `app.js` on `htmx:load`. Forms also declare `method="post"`.
- **Live updates:**
  - The layout no longer loads `sse.min.js`. `app.js` opens one raw `EventSource('/api/events')` and routes `{kind}` frames to the visible view: history, issues, intercept, toollog→logger, ws, organizer, proxy, session, dashboard→sequencer, scope, dashboard, and crawl-watch.
  - It re-fetches through `htmx.ajax` with an `X-Live-Refresh` header.
  - One request runs at a time, with at most one queued after it. A generation counter drops stale answers.
  - If the operator has scrolled down, is focused on a field, or has unsaved edits, a "new data" pill appears instead of refreshing, and those edits are re-applied after a manual refresh.
- **Other `app.js` features:**
  - Keyboard shortcuts: Alt+1..0 switches tools, Alt+T toggles intercept, j/k/↑/↓ and Enter move through rows, Ctrl/Cmd+A selects all, `?` shows help.
  - Shift-click selects multiple rows and updates a count, but no bulk action uses the selection.
  - Theme toggle saved in localStorage; copy buttons via `data-copy`; mobile burger menu; tap-to-expand cells and headers on phones.
- **Phone layout:** CSS only, in `layout.html`, below 640px. Classes `wide-t`, `scope-t`, `sitemap-t`, `rules-t` and `organizer-items` (stacked cards using `data-label`) hide edge columns. `main.split` stacks; the scope edit form docks as a bottom sheet.

## Rendering helpers

- **Escaping:** `html/template` escapes everything. In `ui2_highlight.go`, `span()` is the single place token text gets escaped.
  - `renderMessagePane(raw, isRequest, pretty)` returns `ui2PaneView`.
  - Body types: JSON, HTML/XML, CSS, JS (via tdewolff minify/parse), form data, plain.
  - Bodies over 1 MiB (`highlightMaxBytes`) render raw with a note.
- **Redaction:** `ui2SessionRuleRedact` / `redactSecrets`, `ui2ScopeDisplayRules` (masks credentials in URLs), and `ui2TriageProjection` (hides the API key).
- **Text handling:**
  - `ui2TextareaSafe`: a held message with non-UTF-8 bytes or NUL gets no editor.
  - `ui2NormalizeNewlines` / `ui2RestoreHeaderNewlines`: restore CRLF in the message head after a textarea round-trip.
  - `ui2HostFromRequest`: derives the Repeater target, keeping `https://`.
- **Result rendering:** `ui2APIErrorText`, `ui2ToolOutputText`, `ui2RenderCompare` / `ui2CompareSegs` (rune-safe diff), `ui2RenderSequencerReport`.
